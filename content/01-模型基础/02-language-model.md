**语言模型**为文本序列建立概率模型。自回归语言模型把整段文本的概率拆成多步：每一步根据已有文本预测下一个 Token，再将这些条件概率相乘。[1]

## 预测的是条件概率

直观写法是：`P(整段文本) = P(第1个 Token) × P(第2个 | 第1个) × …`。竖线表示“已知前面的内容”。概率不是从资料库里查到的一条答案，而是模型对后续序列的估计。[1]

假设上下文是“请把这段笔记概括为”，用下面一组自拟概率演示模型怎样选择，数字并非实测：

| 下一个 Token | 假设概率 |
| --- | --- |
| 三 | 0.50 |
| 一 | 0.30 |
| 两 | 0.15 |
| 其他候选合计 | 0.05 |

这里的 0.50 不是“最终摘要有 50% 的概率正确”。它只对应这个上下文中的一次 Token 预测。整段答案是否有依据，需要另外检查。

## 自回归怎样形成整段回答

**自回归生成**每次选择一个 Token，将它接到已生成内容后，再计算下一步。上一轮的选择会改变后续条件。[2]

```text
问题和已有文本 → 下一 Token 分布 → 选择 Token
       ↑                            ↓
       └────── 接上新 Token ─────────┘
                 遇到停止条件后结束
```

例如先生成“三”，后续可能生成“点”；先生成“一”，后续可能生成“句话”。这只是路径示意，真实切分可能把多个字合为一个 Token。

## 概率分布之后还要做选择

**解码**是从预测分布中选择输出的过程。贪心解码选当前概率最高者；采样按分布选择；温度调整分布的尖锐程度，较低温度通常更集中。Top-k 保留概率最高的 k 个候选，Top-p 保留累计概率达到阈值的最小候选集合，再重新归一化采样。[2]

例如上述分布若只用 Top-k 且 k=2，候选只剩“三”和“一”，重新归一化后为 0.625 与 0.375。降低温度也不会提供新的事实证据，因此不能把它当作消除错误的办法。

[RAG](/notes/rag/)通过检索材料改变模型生成时的条件；[工具调用](/notes/agent-and-function-calling/)则由外部程序执行动作。它们承担的职责不同。
