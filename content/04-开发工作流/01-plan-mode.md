**计划模式（Plan Mode）** 是编程 Agent 提供的一种工作模式：模型先阅读代码、运行只读命令、提出实施计划，在用户批准之前不修改源码。[1]

它属于权限模式的一种，与自动执行、逐条确认等模式并列；是否提供、如何进入，取决于具体产品。下面以 Claude Code 的产品说明为例，具体行为以对应版本为准。[1]

## 分析先于编辑

进入计划模式后，模型可以读文件、用 shell 做只读探查，并写下计划，但对源码的编辑会被拦住，直到计划被批准。[1] 计划本身可以先生成、再在文本编辑器里修改（Claude Code 中按 `Ctrl+G` 打开），说明它是可审查的中间产物，而不是最终答案。

进入方式也体现了「模式」的性质：会话内用 `Shift+Tab` 切换，或在单条请求前加 `/plan`；也可以从命令行以计划模式启动，并在项目设置里设为默认。[1]

## 批准与切换

计划完成后，产品会给出处理选项：批准并进入自动执行、批准后逐条确认编辑，或继续计划并说明要改什么。[1] 批准后会话退出计划模式，切到对应的权限模式开始编辑；想再次规划，需要重新切回计划模式。[1]

这和「写完计划就自动实施」不同：批准是显式的，计划和执行之间有一道人工检查点。

## 边界与代价

- 计划模式是产品行为，不是通用规范。不同工具的叫法、可用工具与拦截范围不同，跨产品时不能按名称假设一致。[1]
- 它约束的是改动，不是读取：探查仍会产生命令与输出，计划质量取决于模型读到了什么、是否覆盖关键路径。
- 多一次审批就多一次往返；任务简单时，直接执行再检查往往更快。
- 在允许绕过权限的交互会话里，计划模式的拦截可以被配置绕过，不能把它当成安全边界。[1]

## 和相邻概念的关系

计划模式解决「何时从分析转入执行」，不规定方法。它和 [SDD](/notes/spec-driven-development/) 的区别在于：前者是会话内的工作模式，后者要求把规范贯穿实现与验收，二者可以配合。与 [Superpowers 的对比](/notes/planning-and-superpowers/)单独展开。

它也不替代 [Agent Loop](/notes/agent-loop/) 的运行机制：循环、工具调用与停止条件仍然存在，计划模式只是在开始编辑之前加了一道确认。[上下文工程](/notes/context-engineering/)决定计划阶段能看到哪些材料，[ReAct](/notes/react/) 的边想边做则与它形成对照。
