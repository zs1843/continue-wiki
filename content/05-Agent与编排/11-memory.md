**记忆** 是系统在本次会话之外仍然保留的信息；**状态** 是当前任务进行到哪里的记录。上下文窗口只装载此刻要用的内容，记忆则负责把需要跨轮次保留的内容存到窗口之外，需要时再取回。

## 两种记忆按范围区分

LangChain 的文档按召回范围分两类。短期记忆是 **thread 级**：它跟踪当前会话，作为 Agent 状态的一部分，由 checkpointer 持久化，因此会话可以随时恢复；长期记忆跨会话、跨线程共享，存在自定义 namespace 下，可以随时在任何线程中召回。[1]

OpenAI Agents SDK 的 session 是同类做法的具体实现：每次运行前取出会话历史并拼到输入前面，运行结束后把新产生的内容（用户输入、模型回复、工具调用等）写回 session。[2]

两者的共同点是：模型本身不保存对话，记忆由外部存储和检索逻辑提供。

## 短期记忆受上下文窗口约束

历史会越来越长，完整历史可能放不进窗口，即使放得下，模型也容易被过时或无关内容分散注意，延迟与成本同时上升。[1] 常见做法是限制取回条数、压缩摘要或直接删除旧消息。OpenAI 的 session 提供 `SessionSettings(limit=N)` 限制取回数量，也可以用回调在拼装输入时裁剪历史。[2]

短期记忆的“纠错”往往比“追加”更重要：SDK 文档给出 `pop_item`，用于撤回写错的记录。压缩与裁剪会丢失细节，因此需要保留可回溯的原始记录或摘要来源。

## 长期记忆的三种类型

LangChain 借用认知心理学的分类，把长期记忆分为三类：[1]

| 类型 | 存什么 | Agent 中的例子 |
| --- | --- | --- |
| 语义记忆 | 事实与概念 | 用户偏好、组织信息 |
| 情景记忆 | 经历与行动 | 过去执行过的步骤，用作少样本示例 |
| 程序记忆 | 规则与做法 | 系统提示、项目约定 |

语义记忆有两种组织方式。**资料档（profile）** 是一份持续更新的结构化文档，每次写入都要把旧内容和新信息合并，规模变大后容易出错；**集合（collection）** 是不断追加的文档列表，单条更容易生成，但需要模型自己决定更新还是删除，常见问题是过度插入或过度更新。[1]

程序记忆在实践中很少直接改模型权重或代码，更常见的是修改提示。LangChain 描述了“反思”式做法：把当前指令、近期对话和用户反馈一起交给模型，让它改写自己的指令再存回。[1]

## 什么时候写入记忆

写入可以放在主路径，也可以放到后台。[1]

- **主路径**：在回复用户之前判断并写入。好处是新记忆立即可用、过程对用户可见；代价是增加工具与延迟，模型还要同时兼顾对话与记忆整理。
- **后台**：作为异步任务生成记忆。好处是不拖慢主流程、职责分离；代价是写入频率与触发时机需要设计，更新不及时会让其他线程读到旧状态。

LangChain 举了 ChatGPT 的 `save_memories` 工具作为主路径写入的例子：模型在每条消息上决定是否以及如何调用它。[1]

## 召回与作用域

长期记忆按 namespace 和 key 组织，namespace 常包含用户或组织标识，因此可以做到分层管理和按内容过滤；召回可以结合向量相似度与结构化过滤。[1] 这与 [Embedding](/notes/embeddings-and-similarity/) 和 [检索与重排序](/notes/retrieval-and-reranking/) 用的是同一套机制，只是数据来源不同。

作用域划分本身就是隔离手段：如果记忆按用户分区，召回时就不容易把别人的偏好带进上下文。反过来，namespace 设计粗糙时，隔离只能靠事后过滤。

## 纠错与遗忘

记忆系统真正难的不是写入，而是维持正确。[1]

- 旧记忆会过时。用户换了偏好或项目改了约定，原记录仍然存在，召回后会继续影响回答。
- 新旧记忆会冲突。资料档需要合并，集合需要面对“插入还是覆盖”的选择。
- 有些内容必须删除，例如用户要求清除、涉及隐私或已经失效的凭据。删除需要同时覆盖存储、索引、缓存和日志。
- 召回本身也会出错：相似度高的记忆不一定适用于当前任务。

因此记忆需要版本、来源和失效时间一类的治理字段，也需要定期回看。记忆写错时，系统往往不会报错，只会把错误带进后续很多轮。

## 与检索、上下文的区别

[上下文工程](/notes/context-engineering/)处理“此刻窗口里放什么”；记忆处理“窗口之外长期存什么”；[RAG](/notes/rag/)从资料库取证据，记忆则从交互历史中取事实与经验。三者都依赖检索，但记忆的内容由系统自己生成，因此更容易累积错误，也更需要写入与删除规则。

MemGPT 把这种分层类比为操作系统的虚拟内存：在有限上下文之外维护更大的存储，通过在不同层级之间移动数据来制造“大内存”的印象，并用中断管理控制流。[3] 这是系统设计思路，不代表所有记忆实现都要照搬。

## 一个例子

假设一个编码助手在新会话开始时需要三样东西：项目约定（程序记忆，来自仓库里的说明文件）、用户上次卡住的步骤（情景记忆）、用户偏好的回复风格（语义记忆）。把三者都塞进系统提示会越来越长；更合理的做法是分别存储，按当前任务召回，并在约定变更时更新而不是追加。
