**RAG（Retrieval-Augmented Generation，检索增强生成）** 先寻找相关资料，再将资料与问题一起交给模型生成回答。它可以提供本次任务所需的外部信息，不等于已经把这些信息训练进模型参数。[1][2]

## RAG 连接检索与生成

[![RAG 的资料准备与查询流程](/images/ai-rag-flow.svg)](/images/ai-rag-flow.svg)

图为概念示意：索引用于帮助定位，原文片段提供实际内容；检索到的向量本身不是可以直接展示给读者的文献证据。

## 文档怎样变成可用证据

可以用个人笔记库设计一个小例子。下面是解释性设计，并非已接入本站的功能：

| 准备步骤 | 示例决定 | 为什么这样处理 |
| --- | --- | --- |
| 解析 | 保留正文、小标题和代码块 | 避免把导航或脚注混成正文 |
| 切分 | 先按章节，再处理过长段落 | 尽量让定义和必要条件留在一起 |
| 标识 | 每片保留文档地址、标题锚点、版本 | 回答后能够定位原文 |
| 建索引 | 保存检索表示与片段 ID | 找到候选后仍能取回正文 |
| 更新 | 文档修改后替换相应片段 | 避免新旧规则同时被当成现行依据 |

**Chunk（片段）** 是检索和组装上下文的内容单位。过短可能丢失条件，过长可能夹入无关内容；不能仅凭固定字数认定切分合理。这里采用章节优先是示例取舍，不是适用于所有书籍的标准。[1]

## 用笔记问答走一遍

假设问题是：“MCP 初始化后是否直接调用工具？”

1. 检索找到初始化与工具发现两段，并取回正文。
2. 组装问题和片段，要求回答与引用一一对应。
3. 示例回答解释初始化、能力声明以及按需发现工具的关系，并链接相应章节。
4. 若资料没有说明某个实现是否缓存工具列表，应保留未知，不自行填充该实现细节。

引用地址存在，只能证明地址可访问；还要检查原文是否支持答案中的具体断言。资料缺失、资料过时、取错片段和模型误读，都可能导致错误。因此 RAG 不能自动保证答案正确。

## 与微调和 Agent 的关系

原始 RAG 论文讨论了联合训练的检索器与生成器；常见应用也可以在不更新大模型参数的情况下，把检索材料放入输入。两种语境应区分。[2]

[微调](/notes/training-and-inference/)改变参数；RAG 在回答时提供资料。RAG 流程可以固定执行，不一定需要 [Agent](/notes/agent-and-function-calling/)自主决定检索次数。需要效果证据时，再分别检查检索和回答，见[评估](/notes/rag-evaluation-basics/)。
