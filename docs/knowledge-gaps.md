## 判断“完整”的标准

一条 AI 应用从原理到落地要能走通这条链，每一段都能用自己的话解释清楚，才算知识体系闭合：

模型内部怎样计算 → 参数怎样训练与适配 → 推理怎样运行、成本从哪里来 → 资料怎样进入系统 → 系统怎样编排行动与记忆 → 哪些动作允许执行、边界在哪 → 怎样证明它有效 → 怎样上线、维护与运营

当前笔记在“编排行动”和“工程交付”两段比较厚，其余段落只有入口或完全空白。

## 已有主题的深化项

- RAG：从“能检索到”推进到解析、切分实验、混合检索、权限过滤、增量更新与引用回溯。
- 评估：补评测集设计、评分器选择与统计波动，把“找对材料”和“答对问题”变成可复现的流程。
- 上下文与提示：补结构化输出、压缩与裁剪策略、指令层级与 few-shot 的边界。
- 可观测性：补 trace／span、token 与成本账本、轨迹回放。
- Token 与训练：补采样参数、分词器差异、微调与外挂知识的取舍。

## 建议批次

1. （已完成）架构选型、记忆与状态、安全与权限：把“谁来做、信息怎样接续、什么能动”接上现有 Agent 与 Harness 主线。
2. 推理运行与可靠性：解释慢、贵、失败，以及失败后系统怎样继续。
3. 检索工程化：文档解析、切分、混合检索、权限与增量更新。
4. 评估方法论：评测集、judge、回归与线上指标。
5. 训练与适配：SFT、LoRA、DPO、蒸馏、量化，以及微调与 RAG 的决策。
6. 多模态：图像、文档、语音、生成与跨模态检索。
7. 产品、治理与生态：上线运维、合规、团队协作与信息素养。
