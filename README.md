# note

用于整理书籍、文章中的知识点，以概念定义、必要解释、按需示例和可追溯的来源帮助理解，再通过概念间的关联逐步形成个人知识网络。主题不限于 AI。

打开首页即显示笔记正文，左侧按文件夹浏览，支持静态全文搜索。站点运行时只需现有 Web 服务，不依赖 Node、数据库或模型 API。

## 项目位置

当前目录可直接作为独立 Codex 项目打开。原始选题记录位于项目根目录的 `AI记录`，整理后的公开笔记位于 `content/`，工程与构建配置也都在本目录。

原始记录默认仅在本地保留，已加入 Git 忽略，不会被自动导入、构建或发布。后续补充资料后，仍需整理为 Markdown 并确认发布状态。Git 仓库、依赖和已有产物随工程完整保留，无需因本次迁移重新安装依赖。

远程仓库位于 <https://github.com/zs1843/continue-wiki>，推送到 `main` 会触发 GitHub Actions 构建、测试并发布站点。

## 本地运行

需要 Node.js 22.12+（建议通过 `.nvmrc` 使用 Node 22）。仓库锁定 Astro 6，并保留 `package-lock.json` 以便复现构建。

```sh
nvm use
npm ci
npm run build
npm run preview
```

打开命令输出的本地地址。完整搜索需要构建生成索引，首次阅读请使用 `build` 后的 `preview`。日常编写可运行 `npm run dev`，刷新页面查看修改；开发服务器没有完整搜索索引。

## 浏览与目录

左栏底部只保留图钉按钮，可以切换固定或浮动目录，选择保存在当前浏览器，切换文章和刷新后仍保留。固定时目录常驻并独立滚动；取消固定后，使用顶部菜单按钮临时打开。小于 640px 的手机窄屏暂时使用抽屉，回到较宽窗口时恢复固定偏好。

切换文章时保留左栏目录的滚动位置，右侧新文章从顶部开始。目录折叠状态与滚动位置在正文解析前恢复。

首页直接显示第一篇公开笔记，搜索和站点地图只保留文章稳定地址，不重复收录首页正文。

## 思维导图

左侧「思维导图」目录提供知识总览和按主题分类的导图。点开即可拖动、缩放和折叠分支；点击「全屏查看」扩大画布，退出全屏后回到原页面。节点文字可跳转笔记或对应章节。图形不便阅读时，下方还提供知识点列表。

每篇笔记的 `mindmap` 字段保存精简知识点；导图 Markdown 统一存放在 [`mindmaps/`](mindmaps/README.md)。`npm run build` 会自动更新知识总览和主题导图，新公开笔记会被纳入，草稿不会出现。单独更新可运行 `npm run maps`。

## 更新文章

内容按 [内容整理约定](docs/content-writing.md) 编写：直接解释概念，示例按需添加，关键论断在段落或文末注明出处，并说明与其他概念的关系。书籍记录实际已知的书名、作者、章节或页码；文章保留标题、作者与原文链接。正文不转录选题原话，不写整理过程自述。

只将确认可公开的内容整理到 `content/`。项目根目录的原始记录用于持续收集选题，不自动导入；其他资料仍留在原来的资料工作区，不应把整个资料工作区上传到 Git。

```sh
npm run new -- 01-Agent基础 new-topic "新主题"
```

命令会创建自由书写的草稿，只保留一个可选参考区，不覆盖已有文件。也可以手动新建 Markdown：

```yaml
---
title: 新主题
slug: new-topic
status: draft
mindmap:
  - label: "一个已在正文解释的关键知识点"
order: 80
updated: "2026-11-17"
---
```

- `title` 与 `slug` 必填。slug 使用小写英文、数字和单连字符，整个内容目录唯一。
- 缺省状态为 `draft`。核对后改为 `published`，才会进入正式产物；开发服务器同样仅展示公开文章。
- `order` 为可选非负整数，在同目录内排序；目录按带数字前缀的文件夹顺序生成，显示时去掉前缀。
- 支持子文件夹。移动文章时保留 slug，可保持 `/notes/<slug>/` 地址不变。
- `mindmap` 是可选的关键点数组，每项包含简短 `label` 和可选 `heading` 章节锚点（不带 `#`）。每篇最多 8 项，整理时通常保留 1–4 项。章节改名时同步更新，失效锚点会使检查失败。
- `updated` 是可选的带引号日期，表示最近一次实际核对或修改日期。
- 站内链接使用 `[名称](/notes/new-topic/)`；标题定位可用 `#概念`。
- 首版正文使用标准 Markdown，支持表格、代码块和本地配图，不支持嵌入 HTML、MDX 或网页附件上传。配图放在 `public/images/`，使用 `/images/<小写英文名>.png` 等路径；也支持 JPG、WebP、SVG，构建会检查文件与链接。

## 质量检查

```sh
npm run check   # 元数据、链接、草稿引用、内容目录边界、Astro 类型检查
npm test        # 内容负例及临时目录中的发布、失败和回滚演练
npm run build  # 上述检查、静态构建、搜索索引、产物断链和草稿隔离检查、校验清单
```

Markdown 草稿仍可能存在于 Git 源码中；草稿隔离针对公开站点产物，不等于源码仓库隐私保护。建议仓库设为私有，只有站点工程进入该仓库。

## Git 与发布

本站工程是独立仓库（GitHub：`zs1843/continue-wiki`），不包含资料工作区。`main` 分支推送后由 GitHub Actions 自动构建、测试并通过 SSH 发布到宝塔服务器，线上地址 `https://wiki.zs1843.cn/`。

推送即发布的常规顺序：整理资料 → 新建草稿 → 核对来源 → 标记公开 → 本地 `npm run build` 预览 → 提交并推送 `main` → Actions 校验并切换线上版本。没有 CI 时仍可手动 `npm run deploy`；回滚与服务器配置见 [部署与自动更新](docs/deployment.md)。

详细步骤见 [部署与自动更新](docs/deployment.md)，内容来源与版本见 [来源核对记录](docs/sources.md)。未来接入可视化编辑器时，继续使用 Markdown 作为内容交换格式。
